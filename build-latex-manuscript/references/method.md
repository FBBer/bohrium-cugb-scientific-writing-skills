# LaTeX 写作与编译使用方法

命令中的 `S` 指当前工具目录。在平台上使用 `S=/skills/weekly-skill`，本地从工具根目录运行时使用 `S="$PWD"`。若题目需要中间计划，请按实际材料写入 `/app/work`。

明确要求的引擎用 --engine pdflatex、xelatex 或 lualatex。脚本以项目根为工作目录，尊重源文件魔术注释与 Unicode 宏包。先运行 latexmk，环境缺少时运行引擎并按 .bcf/.aux 选择 Biber/BibTeX，比较辅助文件直至收敛。每轮保留实际命令、退出码和日志。如果期刊模板在类文件中要求 XeTeX 或 LuaTeX，程序按首次编译的明确报错换用对应引擎，在干净目录重新编译。命令行或主文件指定的引擎优先，build.json 的 engine_attempts 记录每次选择及其依据。模板只在带 root/entrypoint 的特定子目录工作时，传那个实际目录为 project，并把相对引用资源一并保留。将外部必需的文件随源码交付。代码不打开 shell escape；若稿件存在外部生成步骤，只处理已提供的源和资源，并明确记录依赖。

按首个实质性错误和对应文件行号修复，每次记录“现象—根因—最小改动—重编结果”。检查缺文件、包冲突、未闭合环境、重复标签、缺字体、未定义文献和引用。保留原数学符号、正斜体、编号、表达含义、图表单元格和小数位，按模板处理题注/图索引/宽表。修复溢出优先断行、对齐和列规格。缺少科学数据时记录缺口。

build 目录产出 source/、manuscript.pdf、build.json、compile.log。PDF 只从当前成功编译复制。打开 log 区分需要再编译的警告与最终未定义引用；打开对应页并检查题注、公式、页边、表头和脚注，保存真实页面预览。用 pdftoppm -f 1 -l 1 -png -r 125 -singlefile manuscript.pdf preview，或使用 PyMuPDF 按相关页渲染。

```sh
python3 "$S/scripts/build.py" /app/work/project main.tex /app/output/latex-build
```

科研图保留原始数据、绘图源码与可编辑矢量文件。中文稿使用中文标注，坐标和图例写明量和单位，误差带注明统计含义。流程图和关系图用中等明度的色标区分阶段或实体，实体名称置于白底。标题、标签、说明文字、框线、分组虚线和连接箭头均用纯黑色（#000000），缩到实际栏宽仍能分清。每个虚线框顶部写出该阶段的任务，箭头只连接实际依赖。表格在列头标单位，量值按有效精度对齐。按模板实际栏宽查看细线、字号、图例和题注。

在干净目录用交付源码二次编译，逐页比较提取文本、页数、公式/表格/引文标记和渲染；PDF 时间戳不作为版面变化依据。把构建和源材料映射写入 result.json 的原契约字段。无法编译时仍交付可编辑源码、准确日志、恢复位置及部分状态。

本地复核使用 TeX Live 2026 和 latexmk 4.88。独立环境安装与模板匹配的 TeX Live 组件及其 BibTeX/Biber、字体、宏包；用 pdflatex --version 和 latexmk -version 记录实际版本。 JSON Schema 的完整校验可选装 jsonschema（本地实测 4.26.0）。正式评测优先采用镜像已有依赖；独立使用时在自己的环境配置。

主文件尚未确定时可传 auto。程序会核实项目内的 % !TeX root 目标和 documentclass，忽略注释示例。有多个可能源稿会列出候选名，此时按题面指定的目标用相对路径编译。
